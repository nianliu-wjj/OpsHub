# 权限认证框架选型与配置

决策日期：2026-11-18。选择 Spring Security，使用 Spring Boot BOM 管理版本，依赖只引入 bootstrap 装配层。

## 选型理由

| 维度 | Spring Security | Sa-Token |
| --- | --- | --- |
| 当前工程集成 | 官方 Boot starter、BOM 统一版本，过滤链与方法权限协作成熟 | 需额外管理 starter 版本和会话配置 |
| 权限能力 | 请求级规则、方法级 `@PreAuthorize`，标准 Authentication 身份上下文 | 注解和 StpUtil API 简洁，角色/权限查询需要业务实现 |
| 会话需求 | 支持会话、Basic、OAuth2/OIDC 等多种模式 | Token 登录、踢人、多端会话等能力易于接入 |
| 后续演进 | 企业统一身份、OIDC/SSO 可逐步接入 | 适合围绕 Token 会话管理构建自有账号系统 |
| 成本 | 概念和配置较多，需要理解过滤链与 CSRF | 常规 Token 登录上手更快 |

OpsHub 目前是 Spring MVC 运维后端，尚无多端 Token 会话需求。优先选择 Spring 官方生态、版本治理和方法级权限能力。Sa-Token 能满足常规权限需求，但其会话便利性暂未成为本项目的主要选型条件。

## 已实现的行为

- `/actuator/health` 及其子路径匿名可访问，其余 `/actuator/**` 需要 ADMIN 角色；其他请求必须认证。
- HTTP Basic 提供初始管理员认证，保留默认 CSRF 保护和会话策略。未开启表单登录，也未全局放行 OPTIONS 或错误路径。
- 认证失败返回 HTTP 401 + Result(A0401)，权限不足或 CSRF 失败返回 HTTP 403 + Result(A0403)；方法权限拒绝也映射为 403。
- `@EnableMethodSecurity` 启用业务方法权限，例如 `@PreAuthorize("hasAuthority('order:write')")`。目前初始账号仅有 ROLE_ADMIN，业务权限需要在后续账号/RBAC 实现中显式授予，不隐式授予全部权限。
- `/auth/me` 返回认证用户名；`/auth/csrf` 返回 CSRF 请求头名称和令牌。
- 审计操作人从 SecurityContext 取认证用户名，非认证上下文回落 system，移除对外部 X-Operator 请求头的信任。

## 启动与调用

必须设置 `OPSHUB_ADMIN_USERNAME` 和 `OPSHUB_ADMIN_PASSWORD_HASH`，后者是 BCrypt 摘要（可使用 BCryptPasswordEncoder.encode 在本地生成）。没有默认明文密码，配置缺失或格式错误启动失败。不要把凭据提交到 Git。

通过 HTTPS 发送 `Authorization: Basic <用户名:密码的Base64>`；Base64 不是加密，生产环境必须由 HTTPS 保护传输。Basic 是初始接入方案，每次认证携带凭据，尚未提供密码登录换 Token 的接口。

写操作先认证调用 GET `/auth/csrf`，保存返回的 JSESSIONID Cookie，再在 POST/PUT/PATCH/DELETE 请求中同时携带该 Cookie、返回的 CSRF 请求头及认证凭据。读请求也需要认证。当前不配置跨域放行，前端采用同源部署。

当前账号位于 InMemoryUserDetailsManager，重启从配置重新加载，不提供注册、修改密码或 RBAC 数据表。后续引入数据库账号时替换 UserDetailsService，并保持 BCrypt 编码；接入企业身份时增加 OAuth2/OIDC 配置。线上限流、账号锁定及统一身份接入属于后续账号体系工作。

## 验证

自动化覆盖匿名访问、错误密码、正确凭据、当前身份、CSRF 令牌获取、非管理员访问监控和缺少 CSRF 的写请求。全模块构建执行 Maven install。
