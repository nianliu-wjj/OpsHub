# 分层架构调整

2026-11-18，按项目的 Spring MVC 分层约定调整：Controller 位于 opshub-api，业务 Service 接口位于 opshub-domain-service，Service 实现位于 opshub-biz-impl。项目无需 RPC Facade 接口。

RbacController 和 SecuritySessionController 从实现/装配层迁入 api。Controller 只处理 HTTP 参数、入口校验和 Result 包装；RbacServiceImpl 实现 RbacService，承担七步模板、密码处理、权限和审计。实现层内部 RbacOperations 承担原有事务、菜单循环及关联校验、缓存版本协调，保持由 Spring 代理调用的事务边界。

共享请求、响应和 Result 迁入新模块 opshub-contract，保留原 Java 包名兼容源码引用。公共组件、基础设施和 Service 接口引用 contract，而不依赖 api，因此没有 api→Service→基础设施→api 的循环。

业务实现位于 biz-impl，domain-service 只保留业务接口，其依赖仅为数据模型和领域模型。api 不引用具体实现，bootstrap 同时装配 api 和 biz-impl。业务接口的 void 方法由 Controller 统一返回 Result.ok(null)。认证装配依赖业务接口，具体数据查询由实现提供。

权限和 OpsLog 声明放到 Service 实现方法上，HTTP 调用和其他通过 Spring Service 代理的调用共享同一权限校验与审计路径。审计的返回值现在是业务结果，模板从 #_result.data 调整为 #_result。URI、HTTP 方法、请求字段、状态码和 Result 结构保持兼容。

首次迁移后运行 mvn clean install，清理旧模块中的 Controller/DTO class。现有测试使用真实 api Controller 和 ServiceImpl，模拟内部持久组件，继续验证 Swagger、HTTP 创建账号、密码编码、权限、冲突响应和缓存行为。历史手册里的 Facade/契约层说明以本修订及 README 为准。
